# assetframe-infra

The AssetFrame website: a Next.js app on Vercel that publishes next-session market research reports, gates Pro content behind Clerk Billing subscriptions, and shows a track record of every prediction scored after the fact.

**Status:** MVP. [`LAUNCH.md`](LAUNCH.md) is the launch runbook for the website and the engine, and lists the outstanding follow-ups.

The reports themselves are generated by the Python engine in [assetframe-scripts](https://github.com/JoeWat2005/assetframe-scripts). This repository holds the website, the database schema and the admin console.

## Features

- Reports browser for each instrument, with a free one-page Snapshot and a paid 3–6 page Pro report
- Report files stay in a private Cloudflare R2 bucket and are served only through `/api/report`, which checks the reader's access and redirects to a signed URL that expires after 120 seconds
- Track record: recent scored results are public, and the full ledger and performance analytics are part of Pro
- Accounts and subscriptions through Clerk and Clerk Billing, synced by a webhook at `/api/webhooks/clerk`
- REST API under `/api/v1`: report listings and track record (public), report detail (API key) and Pro content (API key and Pro subscription), plus market data quotes and history, with an OpenAPI document and per-key or per-IP rate limits
- MCP server at `/api/mcp` (Streamable HTTP), with keyless discovery tools and Clerk OAuth for gated report tools
- Notifications: users who follow an instrument get a web push when a new edition is published, and newsletter subscribers (double opt-in) get an email digest
- Admin console: approve or hide editions, manage the asset universe, queue engine runs and commands, review backtests, search members and read feedback
- Public `/status` page and `/api/health` endpoint for uptime monitoring
- Security headers and an enforced Content Security Policy (`web/next.config.ts`)

## Tech stack

- Next.js 16 (App Router), React 19 and TypeScript
- Tailwind CSS 4, shadcn/ui on Radix UI, GSAP, Recharts and lucide-react
- Clerk (`@clerk/nextjs`) and Clerk Billing
- Neon serverless Postgres, with schema migrations managed by node-pg-migrate
- Cloudflare R2 through the AWS SDK v3 S3 client
- Upstash Redis for rate limiting
- web-push (VAPID) and Resend for notifications
- MCP: `mcp-handler`, `@modelcontextprotocol/sdk` and `@clerk/mcp-tools`
- Vercel hosting, Cron Jobs, Analytics and Speed Insights
- Vitest, Testing Library, vitest-axe and ESLint 9

## Getting started

### Prerequisites

- Node.js 20 (the version CI uses) and npm
- A Clerk application, for sign-in
- For the full feature set: a Neon Postgres database, a Cloudflare R2 bucket, and optionally Upstash Redis, Resend, VAPID keys and a Google Places API key

### Installation

All application code lives in `web/`.

```bash
git clone https://github.com/JoeWat2005/assetframe-infra.git
cd assetframe-infra/web
npm install
cp .env.example .env.local
```

### Configuration

Set these in `web/.env.local` for local development, and in the Vercel project for deployments. Variables prefixed `NEXT_PUBLIC_` are sent to the browser; everything else is server-only. Clerk keys alone are enough to see sign-in working; the other features need their own keys.

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Base URL for absolute links (canonical URLs, Open Graph, sitemap) |
| `NEXT_PUBLIC_PRO_PRICE` | Pro price label shown on the site; should match the Clerk Billing `pro` plan |
| `NEXT_PUBLIC_ANALYTICS_URL`, `NEXT_PUBLIC_GA_URL` | Optional dashboard links shown in the admin console |
| `NEXT_PUBLIC_GA_ID` | Optional Google Analytics 4 measurement ID; enables analytics and the cookie banner |
| `DATABASE_URL` | Neon Postgres connection string. Without it, the site reads `web/content/*.json` instead |
| `DATABASE_URL_DEV` | Not read by the website. The engine's sync script uses it to update the Neon development branch |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` | Clerk API keys |
| `CLERK_WEBHOOK_SECRET` | Signing secret used to verify Clerk webhooks (user deletion and billing events) |
| `ADMIN_EMAILS` | Comma-separated emails that get admin access before roles are set in Clerk |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | Cloudflare R2 credentials and the private bucket that holds report files |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | Web push keys and contact URI; the public key is needed twice so the browser can subscribe |
| `CRON_SECRET` | Shared secret that Vercel Cron sends to the cron routes; they refuse requests without it |
| `RESEND_API_KEY`, `RESEND_FROM` | Resend API key and sender address for alert and billing emails |
| `GOOGLE_MAPS_API_KEY`, `GOOGLE_PLACE_ID` | Optional; powers the `/reviews` page from a Google Business Profile |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Upstash Redis for rate limiting and the engine wake flag. Without them, rate limiting is switched off |
| `UPSTASH_KEY_PREFIX` | Optional key prefix when one Redis database serves several environments; must match the engine |
| `COINGECKO_API_KEY` | Optional CoinGecko key for the crypto fallback in `/api/v1/data/*`; the keyless tier works without it |
| `ASSETFRAME_CONTROL_URL`, `ASSETFRAME_CONTROL_TOKEN`, `CF_ACCESS_CLIENT_ID`, `CF_ACCESS_CLIENT_SECRET` | Optional. When all four are set, admin commands go straight to the engine's control server through Cloudflare Tunnel and Access instead of the Neon queue |

The Upstash variables also accept the Vercel Marketplace names (`UPSTASH_KV_REST_API_URL`, `UPSTASH_KV_REST_API_TOKEN`) and the Vercel KV names (`KV_REST_API_URL`, `KV_REST_API_TOKEN`).

### Running locally

```bash
npm run dev        # http://localhost:3000
```

### Database

The schema is owned by the migrations in `web/migrations/`. `migrate:up` and `migrate:down` read `DATABASE_URL` from `.env.local`.

```bash
npm run migrate:up                    # apply pending migrations (also available as npm run db:setup)
npm run migrate:down                  # roll back the last migration
npm run migrate:create -- <name>      # create a new migration file
```

`web/db/schema.sql` is an outdated snapshot and should not be applied. `web/db/reconcile.sql` contains read-only integrity checks to run against a database after publishing.

### Tests and checks

```bash
npm test            # Vitest: access rules, API shapes, security and accessibility checks
npm run lint        # ESLint
npx tsc --noEmit    # type check
npm run build       # production build
```

CI (`.github/workflows/ci.yml`) runs all four on pushes to `main` and on pull requests, using placeholder Clerk keys for the build.

### Deployment

The site is deployed on Vercel with `web/` as the project root. `web/vercel.json` schedules two cron jobs:

| Route | Schedule (UTC) | Purpose |
|---|---|---|
| `/api/cron/new-editions` | 06:00 daily | Notifies followers by web push and newsletter subscribers by email about newly published editions |
| `/api/cron/engine-health` | 06:30 daily | Emails the admin if the engine is offline or its latest run failed |

Apply database migrations with `npm run migrate:up`, with `DATABASE_URL` pointing at the target database. `LAUNCH.md` has the full launch checklist, including the deploy order for migrations that affect the engine.

## How it works

```text
assetframe-scripts (engine)                     assetframe-infra (this repo)
  report files ----------> Cloudflare R2 ---------> /api/report -> signed URL (120 s)
  editions, scores ------> Neon Postgres ---------> pages, /api/v1, /api/mcp
  run requests <---------- Neon queue / control server <---------- admin console
```

- **Content.** The engine uploads report files to R2 and inserts editions, open calls and scored results into Neon. New editions arrive hidden and appear on the site once an admin approves them. `web/lib/content-db.ts` reads from Neon and caches the catalogue and track record for 300 seconds; if no database is configured, it falls back to `web/content/catalog.json` and `web/content/track-record.json`.
- **Access.** `web/proxy.ts`, the Next.js 16 replacement for middleware, attaches Clerk authentication to page and API requests. `web/lib/entitlements.ts` and `web/lib/access.ts` work out what a user may see from their Clerk metadata, which the billing webhook keeps up to date, and from the `ADMIN_EMAILS` list.
- **Report delivery.** `web/app/api/report/[...key]/route.ts` validates the requested object key. Preview images are public, free files need an account and Pro files need a subscription. It then redirects to a short-lived presigned R2 URL created in `web/lib/r2.ts`.
- **APIs.** `/api/v1` routes use API keys (`web/lib/api-keys.ts`, `web/lib/api-auth.ts`) and sliding-window rate limits (`web/lib/rate-limit.ts`). The MCP server in `web/app/api/mcp/route.ts` exposes the same data as tools, with OAuth discovery routes under `web/app/.well-known/`.
- **Engine control.** The admin console reads and writes the engine coordination tables through `web/lib/engine.ts`. When the control-plane variables are set, `web/lib/control-client.ts` sends allow-listed commands directly to the engine and falls back to the Neon queue if that fails.
- **Notifications.** Follows are stored as watchlists. The cron routes send web push through `web/lib/push.ts` and email through `web/lib/email.ts`, and log each send so that nobody is notified twice.

```text
    ├── public/          Static assets, the push service worker and llms.txt
    ├── tests/           Vitest suites
    ├── next.config.ts   Security headers and Content Security Policy
    ├── proxy.ts         Clerk middleware
    ├── site.config.ts   Brand, site URL, publish schedule, social links and disclaimer
    └── vercel.json      Cron schedules
```

## Related repositories

- [assetframe-scripts](https://github.com/JoeWat2005/assetframe-scripts): the Python engine that generates, scores and publishes reports. It writes report files to R2 and rows to Neon, and this website reads them. The two repositories share no code; the R2 key format and the Neon tables form the contract between them.
